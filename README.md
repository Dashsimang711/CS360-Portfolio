## Mobile Inventory Application

### App Requirements and User Needs

The goal of my mobile application was to create an inventory management app that allows users to keep track of items in an organized and easy-to-use way. The application needed to provide a secure login and account creation system, allow users to add and remove inventory items, display inventory information, and maintain the inventory data using a database. The application also needed to provide low-inventory notifications through SMS when appropriate.

The main user need was to have a simple way to manage inventory from a mobile device. I designed the application so that users could log in, view their inventory, add new items, update inventory information, and remove items they no longer needed.

### Screens and User-Centered Design

Several screens were necessary to meet the application requirements. These included the login screen, create-account screen, inventory screen, add-item screen, and SMS/notification functionality. The inventory screen was designed to display items in an organized grid so that users could quickly find the information they needed.

I focused on keeping the interface simple and consistent. Buttons and text fields were labeled clearly, and the navigation between screens was designed to follow a logical order. The goal was to make the application easy to understand without requiring the user to learn complicated controls.

### Coding Process

I developed the application using Android Studio and Java. SQLite was used to store user accounts and inventory information so that the data could remain available after the application was closed and reopened.

I approached the coding process by developing and testing the application one feature at a time. I first worked on the basic screens and navigation, then added the database functionality and inventory operations. I also worked on login and account creation before adding additional functionality such as low-inventory notifications.

Using smaller steps made it easier to identify problems and correct them without affecting the entire application. These techniques can also be applied to future software projects because breaking a larger problem into smaller components makes development and debugging more manageable.

### Testing and Functionality

Testing was an important part of developing the application because it helped identify problems before completing the project. I tested the application repeatedly after making changes to make sure that screens opened correctly, information could be entered, and database operations worked as expected.

I tested important inventory functions such as creating, viewing, updating, and deleting inventory items. I also tested the login and account creation functionality and verified that inventory information could be retained by the database.

Testing revealed problems such as incorrect resource IDs, XML formatting issues, missing activities, and database-related problems. Fixing these issues helped me understand how the different parts of an Android application work together.

### Innovation and Challenges

One of the biggest challenges was connecting the different parts of the application together while keeping the application functional. The user interface, Java activities, SQLite database, and notification functionality all needed to work together.

I had to troubleshoot problems when certain screens did not load correctly or when information was not being displayed or saved as expected. I used testing and debugging to identify the source of these problems and then made changes to the appropriate files.

This required me to think about the application as a complete system rather than treating each screen as a separate project. Working through these challenges helped me become more comfortable with troubleshooting Android applications.

### Area of Success

The area where I was most successful was implementing the inventory database and connecting it to the application's user interface. I was able to create functionality that allowed inventory items to be added, displayed, updated, and deleted.

I also gained experience connecting Java code with XML layouts and using SQLite to store application data. Getting these components to work together demonstrated my ability to apply the programming concepts learned throughout the course to a complete mobile application.

Overall, this project helped me improve my understanding of Android application development, database management, user-centered design, testing, and debugging. The experience will be useful for future programming projects because I now have a better understanding of how to plan, develop, test, and improve a complete mobile application.
